# 4방향 사각 보드 — 규칙과 움직임

이 문서는 **지금 코드에 실제로 들어 있는 값**을 옮긴 것이다. 기억이 아니라 소스에서 확인했다.
수치를 바꾸면 여기도 같이 고친다. 출처 파일을 항목마다 적어 두었다.

보드는 **14 x 14 사각 격자**다. 한 칸은 상하좌우 4방향으로만 이웃한다.
대각선은 이웃이 아니다 — 매칭에도, 장애물 손상에도 안 낀다.

---

## 1. 칸의 종류

`ColorMatcherCore.cs · Board`

| 값 | 상수 | 뜻 |
|---|---|---|
| `0 … 3` | 색 인덱스 | 일반 블록. 색 수는 `Rules.ColorCount = 4` |
| `-1` | `Empty` | 빈칸. 중력으로 메워지고 리필로 채워진다 |
| `-2` | `Obstacle` | 벽돌. 매칭에 안 끼지만 **중력은 받는다.** 옆이 터질 때만 금이 간다 |

좌표는 `(x, y)` 이고 **y 가 클수록 위**다. `x` 는 0이 왼쪽, `y` 는 0이 바닥이다.

---

## 2. 소거 — 같은 색 정사각형

`Board.FindSquares()`

소거 단위는 **같은 색 정사각형**이다. 선 매칭도 대각 매칭도 없다.

- 최소 한 변 `MinMatch = 2` → **2x2 부터** 터진다
- 3x3, 4x4 처럼 더 큰 정사각형도 하나의 매칭으로 잡는다
- 빈칸과 벽돌은 매칭에 안 낀다 (`IsColor` 가 음수를 거른다)

겹치는 후보는 **큰 것부터** 자리를 차지하고, 이미 다 덮인 후보는 버린다.
그래서 3x3 이 성립하면 그 안의 2x2 들이 따로 세어지지 않는다.

### 점수

`Board.ProcessWave()`

```
한 매칭 점수 = 칸수(size²) × BaseTileScore(10) × 크기배수 × 연쇄배수
크기배수 = 1 << (size - 2)        2x2 = x1,  3x3 = x2,  4x4 = x4
연쇄배수 = 1 + ChainBonus(0.5) × (연쇄단계 - 1)
```

아이템 발동으로 터진 칸은 매칭과 별도로 `칸수 × 10 × 연쇄배수` 를 더한다.

## 3. 조각과 놓기

`Piece.Shapes` — **13종**

```
I  T  S  Z  L  J        (4칸)
I3 V3                   (3칸)
PLUS W5 U5 T5 Z5        (5칸)
```

- 모든 조각은 3칸 이상이고, **어떤 회전에서도 2x2 를 포함하지 않는다.**
  조각 자체로는 절대 터지지 않고, 판에 있던 블록과 합쳐져야 터진다.
- **조각은 나올 때 방향이 정해진다.** 무작위로 0~3번 돌린 채 트레이에 올라오고,
  플레이어가 돌릴 방법은 없다 — 어느 방향으로 나왔느냐가 그 조각을 어디 쓸지를 정한다.
- 놓기는 **덮어쓰기**다. 그 자리에 있던 색은 사라지고 조각 색이 된다.
  단 **아이템은 남는다** — 폭탄 위에 덮어써도 폭탄은 그대로다.
- 벽돌 칸에는 못 놓는다 (`CanPlace` 가 거른다). 옆에 놓아서 깨야 한다.

## 4. 움직임 — 중력과 리필

`Board.ApplyGravity()` · `Board.Refill()`

중력은 **위에서 아래 한 방향 고정**이다. 설정값이 아니다.

1. 한 열의 빈칸을 아래에서부터 메운다.
2. **벽돌도 함께 떨어진다.** 판에 떠 있는 것은 없다. 벽돌은 남은 내구도를 들고 내려간다.
3. 위아래 **순서는 그대로** 지킨다. 벽돌 위에 있던 블록은 벽돌을 통과하지 않고 그 위에 얹힌다.

블록이 안 내려오는 경우는 **아래가 이미 차 있을 때뿐**이다.

리필은 빈칸을 전부 새 색으로 채운다. 판은 늘 꽉 찬 상태로 돌아온다.

### 한 수의 순서

`GameManager.DoStamp()`

```
조각을 찍는다 (덮어쓰기)
  → Resolve: 매칭 찾기 → 아이템 발동 BFS → 벽돌 손상 → 파괴
             → 중력 → 리필 → 다시 매칭 (연쇄가 멎을 때까지)
  → 남은 수 감소
  → 벽돌 추가 (횟수 모드만)
  → 다음 조각
```

연쇄는 **단계(웨이브)마다** 보드 상태를 스냅샷으로 남긴다(`Wave.TilesAfter`).
화면은 그 스냅샷을 따라가며 단계별로 보여준다 — 한 번에 다 터뜨리지 않는다.

## 5. 벽돌

`ObstacleStyle.cs` · `Board.ProcessWave()`

- 내구도 `Rules.ObstacleHp = 2`
- **인접한 칸이 터질 때** 금이 간다. 한 웨이브에 **최대 1** 만 깎인다 —
  큰 폭발 한 번에 여러 단계가 날아가지 않게.
- 내구도가 0이 되면 그 웨이브에 같이 부서지고, 그 자리는 일반 칸이 된다.
- 폭탄 같은 아이템 범위에 들면 그 자리에서 파괴된다.

### 벌칙 벽돌

아무 칸도 안 터진 수를 두면 **랜덤한 자리에 벽돌 하나**가 생긴다 (`Board.PenaltyObstacle`).
그 자리에 아이템이 있었으면 **아이템은 사라지고** 벽돌이 대신 들어선다.

빈 수를 두는 것에 값을 매기는 장치다. 놓기만 하고 아무것도 못 터뜨리면 판이 조금씩 좁아진다.

### 등장 (횟수 모드)

`Rules.ObstaclesAfterMove(movesUsed, totalMoves)`

```
3수 전에는 안 나온다
한 수 걸러 한 번 (짝수 수에만)
개수 = 1 + (진행률 × 2)        →  1개에서 3개까지
```

### 겉모습

가로 3장 × 세로 4켜로 **어긋나게 쌓은 벽돌**이다. 흰 줄눈이 격자를 그린다 —
색 타일에는 격자가 없어서 이것만으로 구분된다.

| 상수 | 값 | 뜻 |
|---|---|---|
| `Scale` | 0.92 | 셀 대비 크기. 색 타일보다 꽉 차야 무겁게 보인다 |
| `RoundFrac` | 0.045 | 거의 직각. 색 타일은 34% 라 형태부터 다르다 |
| `LineFrac` | 0.095 | 굵은 외곽선 |
| `BevelFrac` | 0.16 | 위는 밝고 아래는 어둡게 — 덩어리의 두께 |
| `Stages` | 5 | 손상 그림 수 |

손상 단계는 `StageFor(hp, maxHp)` 가 환산한다. **내구도가 2든 5든 한 대 맞을 때마다
반드시 겉모습이 달라진다.** 상수로 계산하면 멀쩡해 보이다 한 방에 사라진다 (실제로 그런 버그가 있었다).

## 6. 아이템

`ItemType` — 4종. 매칭 칸에 아이템이 있으면 발동하고, 발동으로 터진 칸의 아이템도 연쇄 발동한다.

| 종류 | 범위 |
|---|---|
| `Row` | 그 행 전체 |
| `Col` | 그 열 전체 |
| `Diag` | 두 대각선 전체 |
| `Bomb5` | 5x5 (가장자리에서는 잘린다) |

### 판에서 얻는 조건

`Board.MaybeSpawn(chain, matchTiles, res)`

```
한 단계에 6칸 이상 터지면   → Row / Col / Diag 중 하나
연쇄 2단계에 도달하면       → Row
연쇄 3단계에 도달하면       → Bomb5
```

`==` 인 것이 중요하다. `>=` 로 두면 연쇄가 길어질수록 매 단계마다 또 나온다.

### 상점 폭탄

`Shop.Items` — **폭탄 하나**뿐이다.

쓰면 손에 든 조각이 **1칸짜리 폭탄**으로 바뀐다. 1칸은 매칭이 안 생기므로
`Board.Detonate(x, y)` 가 매칭 없이 그 자리에서 터뜨린다.
던진 칸은 **직접**(흰색), 날아간 5x5 는 **연계**(금색)로 연출된다.

## 7. 화면 — 무엇을 어떻게 보여주는가

`BoardView.cs`

| 층 | 내용 |
|---|---|
| 판 | 후광(흰 20%) → 그림자(잉크, 아래로) → 테두리(잉크) → 바닥(크림) → 격자(민트) |
| 칸 | 타일 스프라이트 (`TileScale = 0.96`) — 같은 색 진한 테두리 + 광택 |
| 덧그림 | 아이템 아이콘 / 벽돌 본체 |
| 고스트 | 조각이 놓일 자리 |
| 범위 | 사라질 칸 예고 |

### 예고 — 흰색과 빨강

| 상황 | 색 | 계산 |
|---|---|---|
| 조각을 놓으면 사라질 칸 | **흰색** | `Board.PreviewStamp` |
| 폭탄이 터뜨릴 칸 | **빨강** | `Board.EffectCells(Bomb5, …)` |

둘 다 **17 rad/s (약 2.7Hz)** 로 깜빡이고 알파는 0.42~0.90 이다.
손에 든 조각이 그 범위에 들면 고스트도 **같은 박자로** 흰색까지 밝아진다 —
따로 놀면 어수선해 보인다.

`PreviewStamp` 는 **실제로 찍어보고 되돌리는** 방식이라 예고와 실제 파괴가 어긋날 수 없다.
아이템 발동 연쇄까지 포함하되, **후속 연쇄는 예고하지 않는다** — 리필이 무작위라 예고할 수 없다.

### 연출 시간

`GameManager` 의 공개 필드. 인스펙터에서 바로 만질 수 있다.

| 이름 | 값 | 내용 |
|---|---|---|
| `stampTime` | 0.34 | 들어올림 → 내려찍기 → 버팀 → 복원 |
| `destroyFlash` | 0.22 | 파괴 번쩍임 |
| `chainStep` | 0.19 | 연쇄 한 단계가 터지는 간격 |
| `chainFall` | 0.32 | 연쇄 단계 사이 낙하 |
| `landTime` | 0.18 | 착지 스쿼시·복원 |
| `fallTime` | 0.42 | 마지막 낙하 |
| `ghostLiftCells` | 2.5 | 터치할 때 손가락 위로 띄우는 칸 수 |

스탬프는 **들어올렸다가 내려찍는다.** 소리와 화면 흔들림은 부드럽게 깔지 않고
**꽂히는 순간**에 맞춘다. 핵심은 부드러움이 아니라 순간적인 타격감이다.

### 낙하 — 무엇이 얼마나 움직이나

`GameManager.ApplyWave` 가 **살아남아 미끄러진 블록**과 **새로 들어온 블록**을 나눈다.

한 열을 콘크리트로 끊어 구간별로 본다. 중력은 순서를 지키므로,
구간 안에서 낙하 전 블록 목록과 낙하 후 블록 목록이 **아래에서부터 1:1 로 대응**한다.

```
i < 살아남은 수   →  떨어진 거리 = 원래 y - 새 y      (보통 1~3칸)
i >= 살아남은 수  →  구간 위에서 새로 들어온 것        (판 밖에서 내려온다)
안 움직인 블록    →  아예 건드리지 않는다
```

거리를 추정하면 한 칸 미끄러진 블록도 판 밖에서 떨어지는 것처럼 보여서,
**열 전체가 통째로 교체되는 것처럼** 읽힌다. 그래서 실제 거리를 계산해 넘긴다.

`stagger` 로 아래쪽이 먼저 자리를 잡게 하고, 위쪽 칸을 그만큼 늦춘다.
착지 흔들림의 세기는 **가장 멀리 떨어진 거리**(`LastMaxDrop`)에 비례한다.

**터진 칸은 그 즉시 시각 상태에서 비운다** (`BurstSegment`). 안 비우면 낙하 전/후 목록이
같은 것으로 보여 이동 거리가 전부 0 이 되고, 애니메이션 없이 칸만 갈아끼우는 것처럼 보인다.

### 어떻게 움직이나

```
거리 = drop × (1 - k²)        k = 0 → 1 (정규화한 시간)
```

**처음엔 느리고 갈수록 빨라진다.** 거리가 시간의 제곱에 비례하는 자유낙하와 같은 모양이다.
ease-out 을 쓰면 빠르게 시작해 감속하므로 중력과 반대로 보인다.

낙하 시간도 거리에 따라 다르다 — `dur × √(거리 / 최대거리)`.
전부 같은 시간에 도착하면 물체가 아니라 화면 전환처럼 보인다.

새로 들어오는 블록은 **판 바로 위**에서 진입하고, 맨 윗줄 위로 걸친 만큼 알파가 빠진다.
안 그러면 판 밖 허공에 타일이 떠 있는 것처럼 보인다.

### 트레이 — 조각을 집어서 놓는다

모바일 기준이다. 트레이는 보드 아래에 **지금 블록과 다음 블록** 두 칸을 보여준다.

```
화면을 누르는 순간  → 지금 블록이 바로 잡힌다 (트레이를 먼저 고를 필요 없다)
끌고 다닌다        → 조각이 손가락을 따라온다
손을 뗀다          → 그 자리에 놓는다. 못 놓는 자리면 그냥 취소된다
```

다음 블록은 **미리보기라 고를 수 없다.** 지금 블록을 쓰면 다음 블록이 그 자리로 당겨지고
새 조각이 다음 자리에 들어온다.

트레이도 **보드와 같은 월드 좌표**에 그린다. 드래그가 한 좌표계 안에서 끝나야
화면 좌표 ↔ 월드 좌표를 오갈 일이 없다.

| 상수 | 값 | 하는 일 |
|---|---|---|
| `TraySlots` | 2 | 지금 블록 + 다음 블록 |
| `CurrentSlot` | 0 | 지금 블록의 자리 |
| `TrayY` | -4.6 | 트레이 중심 (칸 단위, 보드 아래) |
| `TrayCell` | 0.40 | 트레이 안 칸 크기 |
| `TrayRadius` | 1.55 | 슬롯 하나가 차지하는 반경 |
| `GameManager.HudRoom` | 0.095 | 상단 HUD 만큼 보드를 아래로 미는 비율 |
| `GameUI.EdgeMargin` | 26 | 보드 경계와 HUD 줄 사이 간격 |

지금 블록은 1.0 배, 다음 블록은 0.78 배에 알파 0.55 로 흐리게 그린다.
제한시간이 다 되면 기회를 하나 쓰고 다음 블록으로 넘어간다.

화면 아래는 트레이가 쓰므로 **홈(←)은 상단 모서리 아이콘**으로 옮겼다.

### 들고 있는 조각

집은 조각은 **칸에 딱딱 붙지 않고 손가락을 그대로 따라간다.** 칸에 스냅해 그리면
들고 다니는 게 아니라 이미 놓인 것처럼 보인다.

| | 무엇 | 어떻게 |
|---|---|---|
| 놓일 자리 | 스냅된 칸 | 흰 윤곽(`ghostRing`). 놓을 수 없으면 붉은색 |
| 손에 든 것 | 커서 연속 좌표 | 1.01 배로 키우고 0.22 칸 들어올려, 아래에 그림자를 깐다 |

| 상수 | 값 |
|---|---|
| `CarryScale` | 1.01 |
| `CarryLift` | 0.22 |
| `ShadowOffX` / `Y` | 0.07 / -0.16 |

터치일 때는 `ghostLiftCells`(2.5칸)만큼 더 띄운다 — 손가락이 조각을 가리기 때문이다.

## 8. 모드

| | 횟수 | 타임어택 |
|---|---|---|
| 제한 | `Rules.Table["hard"].Moves = 20` 수 | `TimeAttackMs = 180000` (3분) |
| 조각 제한시간 | 4초 (`PieceTimeMaxMs/MinMaxMs`) | 없음 |
| 벽돌 등장 | 있음 | 없음 |
| 리더보드 | 올린다 | 올린다 |

조각 제한시간이 다 되면 그 조각은 버려지고 **기회도 한 번 소모**한다.
아니면 가만히 두는 것만으로 조각을 공짜로 넘길 수 있다.

상점 아이템을 쓰면 **조각 타이머를 다시 시작**한다. 돈을 주고 바꾼 조각이므로
남은 시간이 얼마든 조준할 시간을 준다.

코인은 `ScorePerCoin = 100` → **100점당 1코인**, 버림.

## 9. 내가 만질 수 있는 값

밸런스와 손맛을 바꾸는 값을 한곳에 모았다. **왼쪽이 변수 이름, 오른쪽이 하는 일**이다.
`GameManager` 항목은 유니티 인스펙터에서 게임을 켠 채로도 바꿀 수 있다.

### 게임 난이도 — `stages/stages.json`

**난이도 수치는 코드가 아니라 이 파일이 갖는다.** 스테이지마다 한 줄이다.
값을 바꾸고 게임을 다시 켜면 반영된다 (빌드 불필요).

#### 전체 난이도 손잡이 — 파일 최상단 `difficulty`

```json
{ "difficulty": 3, "stages": [ ... ] }
```

**1(쉬움) ~ 5(어려움), 기준은 3.** 스테이지별 수치는 전부 **3 기준**으로 적혀 있고,
손잡이가 축마다 배율을 곱한다 (`StageTable.ApplyDifficulty`). 판 스무 개를 다시 적지 않고
곡선 전체를 올리고 내리는 자리다.

| 축 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 목표 블록 (`clearBlocks`) | ×0.70 | ×0.85 | ×1.00 | ×1.15 | ×1.30 |
| 수·피스·오염 주기 | ×1.30 | ×1.15 | ×1.00 | ×0.90 | ×0.80 |
| 조각 제한 시간 | ×1.40 | ×1.20 | ×1.00 | ×0.85 | ×0.70 |
| 강철·벽돌 수 | ×0.50 | ×0.75 | ×1.00 | ×1.25 | ×1.50 |

- 오염 주기는 '몇 수마다' 라 예산과 같은 방향이다 — **어려울수록 주기가 짧아진다.**
- **0 은 0 그대로다.** 강철이 없던 판에 강철이 생기지 않고, 1 이상이던 값은 1 밑으로 안 내려간다.
  난이도를 돌린다고 스테이지 종류가 바뀌면 안 되기 때문이다.
- 그림 무늬의 칸 수(`targetPattern`)는 손잡이를 타지 않는다. 무늬가 깨지기 때문이다 —
  좌표 스테이지의 난이도는 수 예산으로 조절된다.

```
stages/stages.json          원본. 밸런싱은 여기만 고친다
Assets/StreamingAssets/     빌드용 사본 (Tools/sync-stages.sh 가 맞춘다)
persistentDataPath/         빌드 후에도 교체 가능한 자리. 있으면 이게 우선한다
```

| 필드 | 하는 일 | 올리면 |
|---|---|---|
| `clearBlocks` | **이만큼 부수면 클리어.** 목표를 채우면 수가 남아도 끝난다 | 어려워진다 |
| `moves` | 쓸 수 있는 수 | 쉬워진다 |
| `pieceTimeMaxMs` | **첫** 조각의 제한 시간(ms) | 여유가 생긴다 |
| `pieceTimeMinMs` | **마지막** 조각의 제한 시간(ms) | 여유가 생긴다 |
| `colorCount` | 판에 쓰는 색 가짓수 | 어려워진다 |
| `obstacleFromMove` | 몇 수째부터 벽돌이 나오나. **0 이면 안 나온다** | 쉬워진다 |
| `obstacleEveryMoves` | 몇 수 걸러 나오나 | 쉬워진다 |
| `obstacleMax` | 한 번에 최대 몇 개 | 어려워진다 |
| `obstacleHp` | 벽돌을 부수는 데 필요한 인접 소거 횟수 | 어려워진다 |
| `penaltyObstacle` | 아무것도 안 터진 수에 벽돌이 생기는가 | — |
| `steelCount` | 판을 열 때 놓는 **못 깨는 강철** 수 | 어려워진다 |
| `pieceLimit` | **0 이 아니면** 이 피스 수 안에 끝내야 한다. `moves` 를 대신한다 | 쉬워진다 |
| `targetPattern` | 표시된 칸 무늬. 비면 좌표 목표 없음 | — |
| `targetCount` | `scatter`/`rows`/`cols` 에서 쓸 수. 그림 무늬는 제 모양대로다 | 어려워진다 |
| `pollutionEvery` | **0 이 아니면** 오염 판. 이 수마다 근원 옆이 오염된다 | 쉬워진다 |
| `pollutionPerSpread` | 한 번에 오염되는 칸 수 | 어려워진다 |
| `kind` | 이 판의 종류 라벨 (설명용). 겹친 판은 `cells+pieces` 처럼 잇는다 | — |

두 조각 시간을 다르게 두면 **뒤로 갈수록 조여든다.**
`PieceTimeMs(movesLeft, totalMoves)` 가 남은 수에 선형 비례해 줄여 준다.

⚠ `colorCount` 는 지금 **4 가 상한**이다. `Palette.Sets` 의 한 벌이 4색이라
5 를 넣으면 같은 색이 두 번 나온다. 늘리려면 팔레트 세트부터 늘려야 한다.

### 스테이지 종류

`StageTargets` · `GameManager.GoalMet`

스테이지는 **다섯 종류**가 순서대로 돈다 (`stages.json` 의 `kind` 가 그 라벨이다).
`kind` 는 읽는 사람을 위한 설명이고 **동작은 아래 수치가 정한다** — 둘이 어긋나면 테스트가 잡는다.

```
1 blocks   2 pieces   3 steel   4 cells   5 pollution   6 blocks …
10·20 은 여러 종류를 겹친 판이다 (10 = cells+pieces, 20 = cells+pieces+pollution)
```

승리 조건은 **둘**이다. 둘 다 걸린 스테이지는 둘 다 채워야 클리어된다.

| | 필드 | 클리어 조건 |
|---|---|---|
| 블록 수 | `clearBlocks` | 이만큼 부순다. **0 이면 이 목표가 없다** |
| 표시된 칸 | `targetPattern` | 표시된 칸을 하나도 남김없이 깬다 |

나머지 둘은 목표가 아니라 **조건**이라 어떤 목표와도 섞인다.

| | 필드 | 하는 일 |
|---|---|---|
| 피스 제한 | `pieceLimit` | 쓸 수 있는 피스 수. 한 수 = 피스 하나라 카운터는 `movesLeft` 그대로 쓰고 HUD 라벨만 `PIECES LEFT` 로 바뀐다 |
| 강철 밭 | `steelCount` · `steelHp` | 강철이 깔린 판. 옆을 `steelHp` 번 터뜨려야 부서진다 |

20단계 구간마다 강철이 굵어진다 — 개수 10→32개, 부수는 횟수 3→7회.
안 깨지는 강철은 오염 근원(`steelHp` 개념 밖, 내구도 0)뿐이다.
| 오염 | `pollutionEvery` · `pollutionPerSpread` | 오염이 번지는 판 |

### 오염 — `GameManager.SpreadPollution`

새 규칙을 만들지 않았다. 판에 이미 있던 두 가지를 그대로 쓴다.

| | 코어 | 성질 |
|---|---|---|
| 오염 근원 | `Board.Steel` | **못 깬다.** 판을 열 때 무작위 한 칸에 심는다 |
| 번진 오염 | `Board.Obstacle` | 매칭에 안 끼고 **옆 칸이 터질 때만** 없어진다 |

- **매 턴 한 칸**씩 번진다 — 블록을 깼든 못 깼든, 조각을 흘려보낸 턴에도 번진다.
- 번지는 자리는 **오염 덩어리 전체의 가장자리**다. 근원 옆 여덟 칸만 보면
  그 여덟이 차는 순간 더 안 번져서, 씨앗은 근원과 이미 번진 오염 전부다.
- 독벽돌은 `pollutionHp`(2)만큼 옆을 터뜨리면 없어진다. 일반 벽돌(3~4)보다 무르다.
- 오염 판에는 **일반 벽돌을 안 놓는다.** 섞으면 생김새가 같아 어느 게 독인지 구분되지 않는다.
- 근원도 **중력을 받아 내려온다.** 그래서 좌표를 기억하지 않고 번질 때마다 다시 찾는다.
- 그 '찾기' 가 **못 깨는 칸이 근원 하나뿐**이라는 전제 위에 있다 —
  그래서 오염과 `steelCount` 는 같은 판에 두지 않는다. 테스트가 이 조합을 막는다.
- 표시된 칸(`targetPattern`) 위에는 근원을 심지 않는다. 못 깨는 칸이 목표를 덮으면 클리어할 수 없다.
- 겉모습: 벽돌·강철 스프라이트를 그대로 쓰고 **색만 물들인다** (`BoardView.SetPollutionStage`).
  오염 판에서는 벽돌이 곧 오염이라 칸마다 표시할 필요가 없다.

**표시된 칸(`targetPattern`)** 은 `StageTargets` 가 정한다. 무늬는 문자열 아트라
새 무늬를 넣는 건 줄 몇 개 적는 일이다.

| 이름 | 무엇 | 칸 수 |
|---|---|---|
| `scatter` | 판 전체에 흩뿌린 `targetCount` 칸 | 지정한 만큼 |
| `rows` / `cols` | 고르게 벌린 행/열 `targetCount` 줄 | 줄당 14 |
| `cross` | 가운데 행 + 가운데 열 | 27 |
| `diamond` `heart` `paw` | 그림 무늬 | 14 / 16 / 22 |

- 표시된 칸은 **블록 바깥을 두르는 3px 테두리**로 보인다 (`BoardView.SetMarks`).
  블록 *뒤* 에 깔면 판 배경에 묻혀 거의 안 보여서, 블록 위(`sortingOrder 3`)에 그린다.
- 남은 칸은 **무지개색으로 반짝인다.** 칸마다 색을 조금씩 어긋나게 줘서 무늬 전체에 색이 흐른다.
- 깨면 사라지지 않고 **흐려진다** — 어디를 이미 깼는지 보여야 남은 칸을 찾는다.
- 강철이 표시된 칸에 올라앉으면 **일반 칸으로 되돌린다.** 아니면 클리어할 수 없는 판이 나온다.

10·20단계는 여러 종류를 겹친 판이다 (`stages.json` 에 직접 적혀 있다).
10단계는 `heart` + 피스 22개, 20단계는 `paw` + 피스 26개 + 오염이다.

⚠ 여기 수치는 **미검증 추정치다.** 무늬 칸 수와 수 예산의 균형은 실제로 플레이해 봐야 안다.

### 스테이지 곡선 — 5단계마다 한 축씩 조인다

| | 1~5 | 6~10 | 11~15 | 16~20 |
|---|---|---|---|---|
| 목표 블록 | 10 → 61 | 77 → 150 | 170 → 254 | 276 → 367 |
| 수 | 30 | 27 | 25 | 23 |
| 조각 시간 | 12→9초 | 10→7초 | 8→5.5초 | 6.5→4.5초 |
| 벽돌 | **없음** | 8수부터 4수마다 1개 | 5수부터 3수마다 2개 | 3수부터 2수마다 3개 |
| 벽돌 내구도 | 2 | 2 | 3 | 3 |
| 벌칙 벽돌 | 6단계부터 | 켬 | 켬 | 켬 |
| **강철** (강철 스테이지에만) | 10개·3회 | 12개·3회 | 14개·3회 | 16개·3회 |

**1~5단계는 규칙을 익히는 구간이다.** 벽돌도 벌칙도 없고 시간도 넉넉하다.
목표 블록 수는 `10 + 9 × (레벨-1)^1.25` 로 늘어난다.

### 못 깨는 강철 — `Board.Steel`

벽돌(`Obstacle`)과 다르다. **무슨 수를 써도 안 부서진다.**

- 매칭에 안 끼고, 위에 놓을 수 없고, 폭탄도 못 뚫는다
- **중력은 받는다.** 빈칸이 생기면 벽돌처럼 내려온다
- 손상 단계가 없다 — 늘 같은 모습이라 '이건 안 부서진다' 가 바로 읽힌다
- 겉모습: 차가운 청회색 금속에 리벳 네 개. 점토색 벽돌과 색부터 다르다

### 클리어와 진행

목표를 다 채우면 **수가 남아도 그 자리에서 클리어**된다.
수를 다 쓰면 실패. 클리어하면 `Progress` 가 다음 스테이지를 연다.

진행도는 상단 아이브로우 줄에 `STAGE 3   24 / 32` 로 뜨고, 목표를 채우면 코랄색이 된다.

결과 화면은 클리어면 **NEXT / RETRY / HOME** 셋, 실패면 **RETRY / HOME** 둘이다.

### 진행 저장 — `Progress`

`PlayerPrefs` 에 로컬 저장한다. **서버 통신이 없다.** 앱을 껐다 켜도 그대로 남고,
기기를 바꾸면 초기화된다.

| 키 | 뜻 |
|---|---|
| `stage_unlocked` | 도전할 수 있는 가장 높은 스테이지 |
| `stage_last` | 지난번에 고른 스테이지 |

홈에서 ◀ ▶ 로 고른다. **안 깬 스테이지는 버튼이 눌리지 않는다** —
`Progress.Selected` 의 setter 가 열린 범위로 눌러 버리므로 코드로도 넘어갈 수 없다.
지난 판으로 되돌아가는 것은 된다.

### 상단 HUD 와 보드가 겹치지 않게

보드는 월드 좌표, 카드는 캔버스 좌표라 화면 비율이 바뀌면 서로 파고든다.
`LayoutHud` 가 **실제 카드 위치를 재서**(`HudBottomScreenY`) 그보다 아래로 보드를 민다.
타이머 줄이 들어갈 여유(`TimerRoom` 1.8칸)까지 계산에 넣는다.

### 코드에 남은 기본값 — `Rules`

파일을 못 읽었을 때만 쓰는 값이다. 밸런스를 여기서 고치지 않는다.
`TimeAttackMs`(180000), `ScorePerCoin`(100), `ObstacleHp`(2) 정도만 남아 있다.

### 판과 매칭 — `ColorMatcherCore.cs · Board`

| 변수 | 지금 값 | 하는 일 |
|---|---|---|
| `W`, `H` | 14, 14 | 판 크기. 바꾸면 화면 배치도 따라 움직인다 |
| `MinMatch` | 2 | 터지는 최소 정사각형 한 변. 3 으로 올리면 3x3 부터 터진다 |
| `BaseTileScore` | 10 | 칸 하나의 기본 점수 |
| `ChainBonus` | 0.5 | 연쇄 한 단계마다 붙는 점수 배수 |

### 아이템이 나오는 조건 — `Board.MaybeSpawn`

```csharp
if (matchTiles >= 6)  → Row / Col / Diag 중 하나     // 한 단계에 터진 칸 수
if (chain == 2)       → Row                          // 연쇄 도달 단계
if (chain == 3)       → Bomb5
```

`==` 를 `>=` 로 바꾸면 연쇄가 길어질수록 매 단계마다 또 나온다. 그래서 `==` 다.

### 보드 바깥에 붙는 HUD

타이머 바와 아이템(폭탄) 줄은 **보드 판 바깥**에 붙는다.

| | 자리 |
|---|---|
| 타이머 바 | 보드 판 **위** 경계 밖 |
| 아이템 줄 | 보드 판 **아래** 경계와 트레이 사이 |

**프로토 좌표로 고정하면 안 된다.** 프로토(390x844)는 화면 비율이 레퍼런스와 다르면
어긋나고, 보드는 월드 좌표라 따로 논다. 실제로 그렇게 두었다가 둘 다 판 위로 올라탔다.

그래서 `GameUI.FollowWorld` 가 매 프레임 맞춘다.

1. 경계의 월드 좌표를 화면 좌표로 바꾼다
2. `RectTransformUtility` 로 그 줄의 부모 기준 좌표를 구한다
3. **실제 사각형을 재서**(`GetWorldCorners`) 경계 바깥으로 `EdgeMargin`(26) 만큼 밀어낸다

크기를 추정하지 않고 재기 때문에 화면 비율이 어떻든 안 겹친다.
패널이 꺼져 있으면 사각형이 0 이므로 한 번만 계산해선 안 된다 — 매 프레임 맞춘다.

폭탄은 이미 장전돼 있으면 다시 눌러도 소모되지 않는다.
안 막으면 누를 때마다 보유량이 계속 깎인다.

### 회전

**회전 조작은 없다.** 버튼도, `R` 키도, 트레이 탭도 없앴다.
조각은 `GameManager.NextPiece()` 에서 무작위로 0~3번 돌린 채 나온다.
돌릴 수 없으므로 '어느 방향으로 나왔나' 가 그 조각의 쓸모를 정한다.

### 손맛과 연출 — `GameManager` (인스펙터 노출)

| 변수 | 지금 값 | 하는 일 |
