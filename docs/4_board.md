# 4방향 사각 보드 — 규칙과 움직임

이 문서는 **지금 코드에 실제로 들어 있는 값**을 옮긴 것이다. 기억이 아니라 소스에서 확인했다.
수치를 바꾸면 여기도 같이 고친다. 출처 파일을 항목마다 적어 두었다.

보드는 **14 x 14 사각 격자**다. 한 칸은 상하좌우 4방향으로만 이웃한다.
대각선은 이웃이 아니다 — 매칭에도, 장애물 손상에도 안 낀다.

---

## 1. 칸의 종류

`ColorMatcherCore.cs · Board`

| 값 | 상수 | 뜻 |
|---|---|---|
| `0 … 3` | 색 인덱스 | 일반 블록. 색 수는 `Rules.ColorCount = 4` |
| `-1` | `Empty` | 빈칸. 중력으로 메워지고 리필로 채워진다 |
| `-2` | `Obstacle` | 벽돌. 매칭에 안 끼지만 **중력은 받는다.** 옆이 터질 때만 금이 간다 |

좌표는 `(x, y)` 이고 **y 가 클수록 위**다. `x` 는 0이 왼쪽, `y` 는 0이 바닥이다.

---

## 2. 소거 — 같은 색 정사각형

`Board.FindSquares()`

소거 단위는 **같은 색 정사각형**이다. 선 매칭도 대각 매칭도 없다.

- 최소 한 변 `MinMatch = 2` → **2x2 부터** 터진다
- 3x3, 4x4 처럼 더 큰 정사각형도 하나의 매칭으로 잡는다
- 빈칸과 벽돌은 매칭에 안 낀다 (`IsColor` 가 음수를 거른다)

겹치는 후보는 **큰 것부터** 자리를 차지하고, 이미 다 덮인 후보는 버린다.
그래서 3x3 이 성립하면 그 안의 2x2 들이 따로 세어지지 않는다.

### 점수

`Board.ProcessWave()`

```
한 매칭 점수 = 칸수(size²) × BaseTileScore(10) × 크기배수 × 연쇄배수
크기배수 = 1 << (size - 2)        2x2 = x1,  3x3 = x2,  4x4 = x4
연쇄배수 = 1 + ChainBonus(0.5) × (연쇄단계 - 1)
```

아이템 발동으로 터진 칸은 매칭과 별도로 `칸수 × 10 × 연쇄배수` 를 더한다.

## 3. 조각과 놓기

`Piece.Shapes` — **13종**

```
I  T  S  Z  L  J        (4칸)
I3 V3                   (3칸)
PLUS W5 U5 T5 Z5        (5칸)
```

- 모든 조각은 3칸 이상이고, **어떤 회전에서도 2x2 를 포함하지 않는다.**
  조각 자체로는 절대 터지지 않고, 판에 있던 블록과 합쳐져야 터진다.
- ROTATE 는 **조각만** 90도 돌린다. 보드도 중력도 회전하지 않는다.
- 놓기는 **덮어쓰기**다. 그 자리에 있던 색은 사라지고 조각 색이 된다.
  단 **아이템은 남는다** — 폭탄 위에 덮어써도 폭탄은 그대로다.
- 벽돌 칸에는 못 놓는다 (`CanPlace` 가 거른다). 옆에 놓아서 깨야 한다.

## 4. 움직임 — 중력과 리필

`Board.ApplyGravity()` · `Board.Refill()`

중력은 **위에서 아래 한 방향 고정**이다. 설정값이 아니다.

1. 한 열의 빈칸을 아래에서부터 메운다.
2. **벽돌도 함께 떨어진다.** 판에 떠 있는 것은 없다. 벽돌은 남은 내구도를 들고 내려간다.
3. 위아래 **순서는 그대로** 지킨다. 벽돌 위에 있던 블록은 벽돌을 통과하지 않고 그 위에 얹힌다.

블록이 안 내려오는 경우는 **아래가 이미 차 있을 때뿐**이다.

리필은 빈칸을 전부 새 색으로 채운다. 판은 늘 꽉 찬 상태로 돌아온다.

### 한 수의 순서

`GameManager.DoStamp()`

```
조각을 찍는다 (덮어쓰기)
  → Resolve: 매칭 찾기 → 아이템 발동 BFS → 벽돌 손상 → 파괴
             → 중력 → 리필 → 다시 매칭 (연쇄가 멎을 때까지)
  → 남은 수 감소
  → 벽돌 추가 (횟수 모드만)
  → 다음 조각
```

연쇄는 **단계(웨이브)마다** 보드 상태를 스냅샷으로 남긴다(`Wave.TilesAfter`).
화면은 그 스냅샷을 따라가며 단계별로 보여준다 — 한 번에 다 터뜨리지 않는다.

## 5. 벽돌

`ObstacleStyle.cs` · `Board.ProcessWave()`

- 내구도 `Rules.ObstacleHp = 2`
- **인접한 칸이 터질 때** 금이 간다. 한 웨이브에 **최대 1** 만 깎인다 —
  큰 폭발 한 번에 여러 단계가 날아가지 않게.
- 내구도가 0이 되면 그 웨이브에 같이 부서지고, 그 자리는 일반 칸이 된다.
- 폭탄 같은 아이템 범위에 들면 그 자리에서 파괴된다.

### 등장 (횟수 모드)

`Rules.ObstaclesAfterMove(movesUsed, totalMoves)`

```
3수 전에는 안 나온다
한 수 걸러 한 번 (짝수 수에만)
개수 = 1 + (진행률 × 2)        →  1개에서 3개까지
```

### 겉모습

가로 3장 × 세로 4켜로 **어긋나게 쌓은 벽돌**이다. 흰 줄눈이 격자를 그린다 —
색 타일에는 격자가 없어서 이것만으로 구분된다.

| 상수 | 값 | 뜻 |
|---|---|---|
| `Scale` | 0.92 | 셀 대비 크기. 색 타일보다 꽉 차야 무겁게 보인다 |
| `RoundFrac` | 0.045 | 거의 직각. 색 타일은 34% 라 형태부터 다르다 |
| `LineFrac` | 0.095 | 굵은 외곽선 |
| `BevelFrac` | 0.16 | 위는 밝고 아래는 어둡게 — 덩어리의 두께 |
| `Stages` | 5 | 손상 그림 수 |

손상 단계는 `StageFor(hp, maxHp)` 가 환산한다. **내구도가 2든 5든 한 대 맞을 때마다
반드시 겉모습이 달라진다.** 상수로 계산하면 멀쩡해 보이다 한 방에 사라진다 (실제로 그런 버그가 있었다).

## 6. 아이템

`ItemType` — 4종. 매칭 칸에 아이템이 있으면 발동하고, 발동으로 터진 칸의 아이템도 연쇄 발동한다.

| 종류 | 범위 |
|---|---|
| `Row` | 그 행 전체 |
| `Col` | 그 열 전체 |
| `Diag` | 두 대각선 전체 |
| `Bomb5` | 5x5 (가장자리에서는 잘린다) |

### 판에서 얻는 조건

`Board.MaybeSpawn(chain, matchTiles, res)`

```
한 단계에 6칸 이상 터지면   → Row / Col / Diag 중 하나
연쇄 2단계에 도달하면       → Row
연쇄 3단계에 도달하면       → Bomb5
```

`==` 인 것이 중요하다. `>=` 로 두면 연쇄가 길어질수록 매 단계마다 또 나온다.

### 상점 폭탄

`Shop.Items` — **폭탄 하나**뿐이다.

쓰면 손에 든 조각이 **1칸짜리 폭탄**으로 바뀐다. 1칸은 매칭이 안 생기므로
`Board.Detonate(x, y)` 가 매칭 없이 그 자리에서 터뜨린다.
던진 칸은 **직접**(흰색), 날아간 5x5 는 **연계**(금색)로 연출된다.

## 7. 화면 — 무엇을 어떻게 보여주는가

`BoardView.cs`

| 층 | 내용 |
|---|---|
| 판 | 후광(흰 20%) → 그림자(잉크, 아래로) → 테두리(잉크) → 바닥(크림) → 격자(민트) |
| 칸 | 타일 스프라이트 (`TileScale = 0.96`) — 같은 색 진한 테두리 + 광택 |
| 덧그림 | 아이템 아이콘 / 벽돌 본체 |
| 고스트 | 조각이 놓일 자리 |
| 범위 | 사라질 칸 예고 |

### 예고 — 흰색과 빨강

| 상황 | 색 | 계산 |
|---|---|---|
| 조각을 놓으면 사라질 칸 | **흰색** | `Board.PreviewStamp` |
| 폭탄이 터뜨릴 칸 | **빨강** | `Board.EffectCells(Bomb5, …)` |

둘 다 **17 rad/s (약 2.7Hz)** 로 깜빡이고 알파는 0.42~0.90 이다.
손에 든 조각이 그 범위에 들면 고스트도 **같은 박자로** 흰색까지 밝아진다 —
따로 놀면 어수선해 보인다.

`PreviewStamp` 는 **실제로 찍어보고 되돌리는** 방식이라 예고와 실제 파괴가 어긋날 수 없다.
아이템 발동 연쇄까지 포함하되, **후속 연쇄는 예고하지 않는다** — 리필이 무작위라 예고할 수 없다.

### 연출 시간

`GameManager` 의 공개 필드. 인스펙터에서 바로 만질 수 있다.

| 이름 | 값 | 내용 |
|---|---|---|
| `stampTime` | 0.34 | 들어올림 → 내려찍기 → 버팀 → 복원 |
| `destroyFlash` | 0.22 | 파괴 번쩍임 |
| `chainStep` | 0.19 | 연쇄 한 단계가 터지는 간격 |
| `chainFall` | 0.32 | 연쇄 단계 사이 낙하 |
| `landTime` | 0.18 | 착지 스쿼시·복원 |
| `fallTime` | 0.42 | 마지막 낙하 |
| `ghostLiftCells` | 2.5 | 터치할 때 손가락 위로 띄우는 칸 수 |

스탬프는 **들어올렸다가 내려찍는다.** 소리와 화면 흔들림은 부드럽게 깔지 않고
**꽂히는 순간**에 맞춘다. 핵심은 부드러움이 아니라 순간적인 타격감이다.

### 낙하 — 무엇이 얼마나 움직이나

`GameManager.ApplyWave` 가 **살아남아 미끄러진 블록**과 **새로 들어온 블록**을 나눈다.

한 열을 콘크리트로 끊어 구간별로 본다. 중력은 순서를 지키므로,
구간 안에서 낙하 전 블록 목록과 낙하 후 블록 목록이 **아래에서부터 1:1 로 대응**한다.

```
i < 살아남은 수   →  떨어진 거리 = 원래 y - 새 y      (보통 1~3칸)
i >= 살아남은 수  →  구간 위에서 새로 들어온 것        (판 밖에서 내려온다)
안 움직인 블록    →  아예 건드리지 않는다
```

거리를 추정하면 한 칸 미끄러진 블록도 판 밖에서 떨어지는 것처럼 보여서,
**열 전체가 통째로 교체되는 것처럼** 읽힌다. 그래서 실제 거리를 계산해 넘긴다.

`stagger` 로 아래쪽이 먼저 자리를 잡게 하고, 위쪽 칸을 그만큼 늦춘다.
착지 흔들림의 세기는 **가장 멀리 떨어진 거리**(`LastMaxDrop`)에 비례한다.

**터진 칸은 그 즉시 시각 상태에서 비운다** (`BurstSegment`). 안 비우면 낙하 전/후 목록이
같은 것으로 보여 이동 거리가 전부 0 이 되고, 애니메이션 없이 칸만 갈아끼우는 것처럼 보인다.

### 어떻게 움직이나

```
거리 = drop × (1 - k²)        k = 0 → 1 (정규화한 시간)
```

**처음엔 느리고 갈수록 빨라진다.** 거리가 시간의 제곱에 비례하는 자유낙하와 같은 모양이다.
ease-out 을 쓰면 빠르게 시작해 감속하므로 중력과 반대로 보인다.

낙하 시간도 거리에 따라 다르다 — `dur × √(거리 / 최대거리)`.
전부 같은 시간에 도착하면 물체가 아니라 화면 전환처럼 보인다.

새로 들어오는 블록은 **판 바로 위**에서 진입하고, 맨 윗줄 위로 걸친 만큼 알파가 빠진다.
안 그러면 판 밖 허공에 타일이 떠 있는 것처럼 보인다.

### 트레이 — 조각을 집어서 놓는다

모바일 기준이다. 조각은 **보드 아래 트레이**에 세 개 놓인다.

```
누르는 순간 트레이 슬롯 위      → 그 조각을 집는다 (슬롯이 들어올려진다)
그대로 보드로 끌고 가서 뗀다    → 그 자리에 놓는다
집은 채로 손을 떼고 보드를 누른다 → 그 자리에 놓는다
놓을 수 없는 자리에서 떼면      → 집은 상태만 유지된다
```

트레이도 **보드와 같은 월드 좌표**에 그린다. 드래그가 한 좌표계 안에서 끝나야
화면 좌표 ↔ 월드 좌표를 오갈 일이 없다.

| 상수 | 값 | 하는 일 |
|---|---|---|
| `TraySlots` | 3 | 슬롯 수 |
| `TrayY` | -3.4 | 트레이 중심 (칸 단위, 보드 아래) |
| `TrayCell` | 0.62 | 트레이 안 칸 크기 |
| `TrayRadius` | 2.05 | 슬롯 하나가 차지하는 반경 = 터치 판정 범위 |
| `GameManager.HudRoom` | 0.13 | 상단 HUD 만큼 보드를 아래로 미는 비율 |

쓴 슬롯은 비고, **세 칸이 다 비면 한꺼번에** 새로 채운다.
제한시간이 다 되면 기회를 하나 쓰고 트레이를 통째로 새로 뽑는다.

화면 아래는 트레이가 쓰므로 **홈(←)과 회전(↻)은 상단 모서리 아이콘**으로 옮겼다.

### 들고 있는 조각

집은 조각은 **칸에 딱딱 붙지 않고 손가락을 그대로 따라간다.** 칸에 스냅해 그리면
들고 다니는 게 아니라 이미 놓인 것처럼 보인다.

| | 무엇 | 어떻게 |
|---|---|---|
| 놓일 자리 | 스냅된 칸 | 흰 윤곽(`ghostRing`). 놓을 수 없으면 붉은색 |
| 손에 든 것 | 커서 연속 좌표 | 1.10 배로 키우고 0.22 칸 들어올려, 아래에 그림자를 깐다 |

| 상수 | 값 |
|---|---|
| `CarryScale` | 1.10 |
| `CarryLift` | 0.22 |
| `ShadowOffX` / `Y` | 0.07 / -0.16 |

터치일 때는 `ghostLiftCells`(2.5칸)만큼 더 띄운다 — 손가락이 조각을 가리기 때문이다.

## 8. 모드

| | 횟수 | 타임어택 |
|---|---|---|
| 제한 | `Rules.Table["hard"].Moves = 20` 수 | `TimeAttackMs = 180000` (3분) |
| 조각 제한시간 | 4초 (`PieceTimeMaxMs/MinMaxMs`) | 없음 |
| 벽돌 등장 | 있음 | 없음 |
| 리더보드 | 올린다 | 올린다 |

조각 제한시간이 다 되면 그 조각은 버려지고 **기회도 한 번 소모**한다.
아니면 가만히 두는 것만으로 조각을 공짜로 넘길 수 있다.

상점 아이템을 쓰면 **조각 타이머를 다시 시작**한다. 돈을 주고 바꾼 조각이므로
남은 시간이 얼마든 조준할 시간을 준다.

코인은 `ScorePerCoin = 100` → **100점당 1코인**, 버림.

## 9. 내가 만질 수 있는 값

밸런스와 손맛을 바꾸는 값을 한곳에 모았다. **왼쪽이 변수 이름, 오른쪽이 하는 일**이다.
`GameManager` 항목은 유니티 인스펙터에서 게임을 켠 채로도 바꿀 수 있다.

### 게임 난이도 — `ColorMatcherCore.cs · Rules`

| 변수 | 지금 값 | 하는 일 | 올리면 |
|---|---|---|---|
| `Table["hard"].Moves` | 20 | 횟수 모드에서 쓸 수 있는 수 | 쉬워진다 |
| `TimeAttackMs` | 180000 | 타임어택 제한 시간(ms) | 쉬워진다 |
| `PieceTimeMaxMs` | 4000 | **첫** 조각의 제한 시간(ms) | 여유가 생긴다 |
| `PieceTimeMinMs` | 4000 | **마지막** 조각의 제한 시간(ms). Max 와 같으면 고정 | 여유가 생긴다 |

두 조각 시간을 다르게 두면 **뒤로 갈수록 조여든다.** `PieceTimeMs(movesLeft, totalMoves)` 가
남은 수에 선형 비례해 줄여 준다. 지금은 둘 다 4000 이라 고정이다.
