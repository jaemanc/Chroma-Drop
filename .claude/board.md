# 보드 뷰 형식과 방식

`Assets/Scripts/GraphBoardView.cs` 가 판을 그리는 규칙. 이 문서는 **왜 그렇게 그리는지**를
남긴다. 수치를 바꿀 일이 있으면 여기 표를 같이 고친다.

보드는 그래프다. 뷰는 셀의 **다각형(`Cell.Poly`)** 과 **중심(`Cell.Center`)** 만 받아 그리며,
가로·세로·열 같은 개념을 쓰지 않는다. square / triangle / hex 가 같은 코드로 그려진다.

---

## 1. 쌓는 순서

한 셀은 다섯 겹이다. 스프라이트를 쓰지 않으므로 **형태와 색만으로** 블록 느낌을 낸다.

| 순서 | 이름 | 크기 | 역할 |
|---|---|---|---|
| 0 | `rim` | `CellInset` | 같은 색을 어둡게(`×0.72`) 칠한 테두리. 블록 경계를 또렷하게 한다 |
| 1 | `cell` | `× FaceInset` | 블록 면. 팔레트 색 그대로 |
| 2 | `gl` | `× GlossInset` | 위로 살짝 올린 흰색 18% 광택 |
| 3 | `ov` | `× 0.5` | 장애물 속 표시 (brick 손상도 / frozen 결정 / locked 심) |
| 4 | `gh` | `CellInset` | 고스트와 예고. 평소엔 꺼져 있다 |

판 자체도 네 겹이다. 배경 일러스트에 묻히지 않게 하는 것이 목적이다.

```
halo(흰 22%) → shadow(잉크 35%, 아래로) → border(잉크) → surface(크림 96%)
```

패널은 **요청 영역이 아니라 셀이 실제 차지한 범위**에 맞춘다. 토폴로지에 따라 가로·세로 중
한쪽만 꽉 차기 때문에, 요청 영역에 맞추면 한쪽이 크게 빈다.

---

## 2. 모서리

`RoundedMesh(poly, center, inset, cut)` 가 꼭짓점을 깎아 둥글게 만든다.
꼭짓점 하나를 세 점(뒤로 물러난 점 → 살짝 당긴 점 → 앞으로 물러난 점)으로 바꾼다.

`cut` 부호가 의미를 가른다.

- **양수**: 변 길이 대비 비율. 칸처럼 크기가 고른 도형에 쓴다 (`CellCut = 0.26`)
- **음수**: 그 절대값을 월드 거리로 본다. 판처럼 변이 긴 도형에 쓴다 (`PanelRadius = 0.42`)

비율만 쓰면 긴 변에서 모서리가 과하게 잘려 판이 팔각형이 된다. 실제로 한 번 그렇게 됐다.

---

## 3. 크기와 배치

`Render.Layout` 이 다각형 전체의 바운딩박스를 보드 영역에 맞춰 **스케일·센터링**한다.
셀 크기를 상수로 두지 않는 이유가 이것이다 — 토폴로지가 바뀌어도 같은 자리를 채운다.

`Layout` 이 이미 영역 안에서 가운데로 맞추므로, 뷰는 **영역의 중심만 원점으로 옮긴다.**
여기서 한 번 더 밀면 판이 한쪽으로 쏠린다 (실제로 그렇게 깨진 적이 있다).

| 상수 | 값 | 자리 |
|---|---|---|
| `BoardWidthFrac` | 0.94 | `GameManager` — 화면 가로 대비 판 너비 |
| `BoardHeightFrac` | 0.58 | 화면 세로 대비 판 높이 |
| `BoardCenterFrac` | 0.53 | 화면 위에서부터 판 중심까지의 비율 |
| `CellInset` | 0.97 | 셀 사이 간격. 1 에 가까울수록 블록이 크다 |
| `PanelPad` | 0.16 | 셀 바깥 여백 |
| `PanelBorder` | 0.16 | 판 테두리 두께 |

## 4. 터치 판정

`Render.HitTest` 의 **point-in-polygon**(교차수)을 쓴다. 사각 히트박스를 쓰지 않는다 —
육각·삼각에서 이웃 칸을 잘못 집기 때문이다.

다각형은 루트 로컬 좌표로 **한 번 옮겨 저장**해 두고, 그리기와 판정이 같은 값을 본다.
따로 계산하면 어긋난다.

셀이 화면에서 44pt 미만이면 `Render.TouchWarning` 이 경고를 남긴다. 규칙이 아니라 품질 신호다.

---

## 5. 강조 — 고스트와 예고

둘은 다른 것이다. 섞으면 "여기 놓인다"와 "여기가 사라진다"가 구분되지 않는다.

| | 대상 | 표현 |
|---|---|---|
| 고스트 | 조각이 놓일 칸 중 **안 사라지는** 칸 | 조각 색 90%, 깜빡이지 않음 |
| 예고 | 놓으면 **사라질** 칸 | 흰색, 알파 0.25~0.92 로 깜빡임 (17 rad/s) |
| 아이템 | 아이템이 미칠 칸 | 빨강, 같은 박자로 깜빡임 |

예고는 `GameEngine.PreviewPlace` 가 계산한다. **실제로 놓아 보고 되돌리는** 방식이라
판정이 실제 소거와 어긋날 수 없다. 조각이 놓일 칸도 사라질 대상이면 예고 쪽에 들어간다.

## 6. 연출

핵심은 부드러움이 아니라 **순간적인 타격감**이다. 이징도 그렇게 잡았다.

**놓기 — `StampCells`** (기본 0.34초)

```
들어올림 34%  →  내려찍기 16%  →  버팀 10%  →  복원 40%
1.0 → 1.24       1.24 → 0.82      0.82        감쇠 진동으로 1.0
```

내려찍기는 `k²` 로 가속한다. 소리와 화면 흔들림은 **꽂히는 순간**(`onImpact`)에 맞춘다.
복원은 `exp(-6k)·cos(3.2πk)` 감쇠 진동이라 툭 튀고 잦아든다.

**소거 — `FlashCells`** (0.20초)

사라지기 **직전에 먼저 번쩍이고** 없앤다. 순서를 지켜야 인과가 읽힌다.

- 1단계: 흰색 — 방금 놓은 수가 직접 만든 소거
- 2단계 이상: 금색 — 무너져서 생긴 연계

연쇄는 `GameEngine.ResolveOnce` 로 **한 단계씩** 처리한다. `ResolveAll` 로 한 번에 돌리면
중간 상태를 보여줄 수 없어 "갑자기 다 터진다"로 보인다.

**낙하 — `DropIn`** (0.18초)

`ResolveOnce` 가 낙하·리필 전후를 비교해 돌려준 **새로 채워진 칸만** 튀어 들어온다.
판 전체가 들썩이지 않는다.

---

## 7. 색

팔레트는 `PaletteGen` 이 시드로 만든다. **코드에 색 리터럴을 두지 않는다.**
톤 조정은 `stages/curve.config.json` 의 `palette` 에서 한다 (채도·명도·색상환 폭).

장애물만 고정색이다. 팔레트 색과 헷갈리면 안 되므로 무채색 계열로 잡았다.

| 대상 | 색 |
|---|---|
| 테두리 | 면 색 × 0.72 |
| 빈칸 | `(0.92, 0.96, 0.95, 0.55)` |
| locked | `(0.24, 0.27, 0.33)` + 밝은 심 |
| brick | `(0.66, 0.47, 0.42)` + 내구도에 따라 밝아지는 속 |
| frozen | `(0.62, 0.82, 0.90)` + 흰 결정 |

## 8. 고칠 때 확인하는 것

- 세 토폴로지를 **모두** 렌더해 본다. square 만 보고 넘어가면 삼각·육각이 깨진 걸 놓친다.
- `./Tools/verify.sh` 의 V24(다각형 겹침·히트박스)와 V6(축 직선)이 여전히 통과하는지 본다.
- 배경 일러스트를 깔고 본다. 판만 따로 보면 "묻힌다"를 못 잡는다.
