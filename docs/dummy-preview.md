# 더미 앱 확인

현재 `TestServices.Enabled`가 켜져 있어 에디터와 기기에서 결제·랭킹·광고를 외부
서비스 없이 확인할 수 있다. 실제 결제 청구와 Firebase 요청은 하지 않는다.

## 직접 확인

1. Menu에서 일반 모드 또는 타임어택을 시작한다. 현재 세 테마는 원본 10×10에서
   11×11로 늘었다. 보드 내부 영역은 중심을 유지하며 10% 커지고, 블록도 이전 화면
   크기보다 10% 커진다. 배경에 그려진 10×10 격자는 실제 11×11 격자로 덮는다.
2. 상점의 BUY COINS를 연다. TEST COINS와 실제 청구가 없다는 안내를 확인한다.
   세 상품을 누르면 300 / 850 / 1,800 코인이 지급된다.
3. 취소 테스트를 누르고 상품을 고른다. 잔액과 결제 기록이 늘지 않는다.
4. 실패 테스트를 누르고 상품을 고른다. 지급되지 않고 미완료 주문이 남는다.
   주문 재시도를 누르면 해당 주문을 한 번 지급한다.
5. 주문 재시도를 다시 누른다. 이미 지급된 주문은 잔액이나 기록을 늘리지 않는다.
   앱을 다시 실행한 뒤에도 주문과 잔액이 유지된다.
6. 상점 아이템·스킨 구매로 코인을 소비하고 주문 재시도를 누른다. 소비한 잔액을
   이전 값으로 되돌리거나 추가 지급하지 않는다.
7. WATCH AD는 3초 테스트 화면이 끝나면 기존 광고 보상을 지급한다.
8. 랭킹에는 Test Player 샘플과 내 최고 기록이 나온다. 개인·국가 순위를 전환한다.
   더 낮은 점수를 제출해도 내 최고점은 유지된다.

## 기록과 저장

테스트 결제는 PlayerPrefs의 `chromadrop_test_wallet_v1`에 JSON으로 저장한다.
`coins`, 미완료 `pending`, 완료 `pay`를 한 JSON으로 갱신하므로 기록과 지급이
따로 저장되지 않는다. 상품 ID, 더미 거래 ID, 표시 가격(원), 지급 코인, 시각,
`store: dummy`, `status: granted`가 기록된다. Firestore에 기록한 실제 결제가 아니다.

기존 로컬 코인은 첫 테스트 지갑 생성 시 복사하고, 이후 소비·보상도 같은 테스트
지갑을 사용한다. 기존 개발 코인 지급 절차는 유지한다. 운영 지갑 키·Firebase 인증
세션·운영 랭킹 기록은 덮어쓰지 않는다. 랭킹은 `dummy_rank_` 키로 따로 저장한다.

`TestServices.Enabled`를 끄는 것만으로 실결제가 연결되는 것은 아니다.
사용자 검토가 끝난 뒤 스토어 SDK, 서버 인증·영수증 검증, Firebase 지급 API와
앱 지갑을 연결한다. `Backend/payments/`의 서버 지급 모듈은 그때 사용할 준비 코드다.

## 회귀 검사

Unity PlayMode의 `SceneSmokeTests`는 보드 11×11과 크기 보정을 확인한다.
`TestServicesTests`는 결제·취소·실패·재시도·소비, 더미 최고점,
실제 상점 버튼 및 광고 보상 경로를 검사하고 기존 테스트 저장값을 복구한다.
실행 결과는 별도 검증 기록에서 확인한다.
